# Failure matrix — OpenCode V2 two-level coordination

OpenCode's V2 HTTP API is declared experimental, including its session routes. The Action column is orchestrator policy, not a runtime promise. Before each operation, consult the confirmed instance's `/openapi.json` and follow the [verify-effects rule](#verify-effects-before-retrying). [API V2](https://opencode.ai/v2/docs/api/)

## Verify effects before retrying

1. Check whether the exact session already exists and whether its `location`/`parentID` are the expected ones. If the creation response was lost, the result stays unknown until reconciled.
2. Check through published read interfaces whether the prompt/message was accepted, executed, or is pending approval. If the reads do not cover the whole result, do not resend.
3. Inspect the artifacts and write effects in the authorized scope before resuming or reassigning the work.
4. After a worker interruption, reconcile every subagent and its approvals. Do not release overlapping scopes while any execution is still active or unknown.
5. Retry only after confirming the absence of prior work and effects, preserving authorization and scope, and using arguments published by the instance.

## `attach-tabs` exit codes (round 6, XOS-09)

The `attach-tabs` subcommand emits a stable set of exit codes. Callers
(orchestrate `init-run`, smoke runners, CI consumers) must discriminate them:
collapsing several meanings to the same number is documented here, not treated
as a shrunk contract.

| Code | Meaning | Where raised |
|---|---|---|
| `0` | ok-verificada-title — merge wrote and the readback found the tab with the expected `title` under the requested `tui_cwd` | `TABS_MERGE_PY` rc 0 (`SKILL/scripts/os/_common.sh`) |
| `2` | usage error / gate fail / session not found / no python3 in adapter / helper creation failed. Keep fail-closed semantics; surface the reason on stderr | `sub_attach_tabs` (`--session` missing,, gate != ready without `--force-tabs`, `--tui-cwd` mismatch / missing / nonexistent); OS adapters `python3 missing` / `helper creation failed` (windows-gbash) |
| `3` | state on `/mnt/*` (drvfs) — POSIX locks unreliable across Win↔Linux processes; the tab is marked "not verified" | wsl.sh `os_tabs_merge` |
| `4` | no TUI / `tabs.json` missing | `tabs_status=no-tui`; `tabs_json_path` rc 4 → bubbled up by the merge engine |
| `5` | readback-fail — the merge wrote but the readback could not find the tab / title under `tui_cwd` | `TABS_MERGE_PY` rc 5 |
| `6` | schema mismatch — `tabs.json` shape diverges from the assumption (concurrent write or unrecognized schema); the merge fails closed with the file intact | `tabs_status=fail-closed-esquema-distinto` (rc 6) |
| `70` | lock helper fail-closed (python3 missing, no fcntl, lock file unusable, or command could not launch) — nothing was written | `lock_exec` rc 70 |
| `71` | lock busy after the bounded wait — do not retry silently; raise or reassign | `lock_exec` rc 71 |

**Collision note:** `70/71` are also reachable as a *wrapped command's*
own exit code, propagated 1:1 by the lock helper. The discriminator is the
`lock_status=fail-closed` line on stderr, printed **only** by the helper's own
failures. Remapping the collision (e.g. to `72`) is deliberately NOT done:
silently rewriting a legitimate `rc` would break the caller's contract, and
the call graph under `lock_exec` (merge helpers + critical-section guards)
never wraps a command that exits `70`/`71`.
