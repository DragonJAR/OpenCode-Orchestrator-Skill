# Matriz de fallos — coordinación OpenCode V2 de dos niveles

La API HTTP V2 de OpenCode se declara experimental, incluidas sus rutas de sesión. La columna Acción es política del orquestador, no promesa del runtime. Antes de cada operación consulta el `/openapi.json` de la instancia confirmada y sigue la [regla de verificación de efectos](#verificación-de-efectos-antes-de-reintentar). [API V2](https://opencode.ai/v2/docs/api/)

| Fallo | Señal observable | Acción | No hacer | Anclaje |
|---|---|---|---|---|
| Preflight incompleto | Instancia, versión, `/openapi.json`, permisos o agente destino no confirmados | Bloquea despacho y registra la evidencia que falta | Adivinar endpoint, ruta, agente o permiso | [API V2](https://opencode.ai/v2/docs/api/), [Agents V2](https://opencode.ai/v2/docs/agents) |
| API HTTP ausente/no autorizada | Endpoint no responde, ruta no aparece en `/openapi.json` o acceso denegado | No crees la sesión por mecanismos no documentados; deja el run bloqueado y solicita la capacidad autorizada | Buscar secretos fuera de la excepción acotada de [recipe-tui-tabs.md](recipe-tui-tabs.md#autenticación-http-directa-solo-si-hace-falta), escanear puertos o cambiar de transporte para evadir una denegación | [API y sesiones](api-and-sessions.md) |
| Creación de worker sin ID confirmado | Timeout/error de `POST /api/session` sin `sessionID` inequívoco | Reconcilia las sesiones existentes por las rutas publicadas antes de repetir; conserva estado desconocido | Reenviar a ciegas y crear duplicados | [API V2](https://opencode.ai/v2/docs/api/) |
| Worker raíz mal tipado | `parentID` runtime no es `null` o el ledger le asigna padre | Detén el flujo y corrige/reconcilia identidad; solo el orquestador corrige el ledger | Tratar una sesión hija como tab/worker raíz | [ledger-template.md](ledger-template.md) |
| Tab no disponible o no visible (solo si el usuario pidió tabs) | `tabs.mode: off`, cliente sin selector o sesión no aparece tras crear | Mantén separadas creación y presentación; usa la acción de TUI documentada o el método local sujeto a versión en [recipe-tui-tabs.md](recipe-tui-tabs.md), luego verifica el `sessionID`. Si no se puede verificar, bloquea la afirmación de éxito | Editar estado sin comprobar versión, scope y schema; reiniciar como recuperación automática; asumir que HTTP abrió una tab | [TUI V2](https://opencode.ai/v2/docs/cli/tui/), [CLI plugin API](https://opencode.ai/v2/docs/build/plugins/cli/), [config CLI](https://opencode.ai/v2/docs/cli/config) |
| Schema privado de tabs desconocido o escritura concurrente | JSON corrupto, forma distinta, rename fallido o TUI modificó tabs durante el merge | Conserva el archivo previo y detén la escritura. Antes de reintentar, confirma versión/scope/schema y asegura el mismo lock `Flock` o exclusión efectiva del escritor TUI durante lectura/merge/rename/readback; si no puedes, no edites `tabs.json`, usa una interfaz documentada de tabs ya disponible o marca la tab como no verificada | Reemplazo ciego, borrar primero, reintentar sin exclusión o asumir que escritura atómica evita pérdida por carrera | [Receta local de tabs](recipe-tui-tabs.md), [storage upstream v2.0.21](https://github.com/anomalyco/opencode/blob/v2.0.21/packages/tui/src/context/storage.tsx) |
| Identidad de tab ambigua | La tab visible no puede asociarse al ID de la sesión creada | Usa una interfaz de cliente documentada que exponga el ID; de lo contrario no verifiques | Usar índice, título o color de tab como `sessionID` | [CLI plugin API](https://opencode.ai/v2/docs/build/plugins/cli/) |
| Ubicación diferente/desconocida | `Session.Info.location.directory` difiere de `run.location.directory` o no se puede leer | No despaches; confirma ubicación exacta en la misma instancia. Aplica el valor canónico del servidor literalmente en todos los sistemas cliente | Reescribir separadores, asumir que la ruta local del cliente es la ruta del servidor | [API V2](https://opencode.ai/v2/docs/api/) |
| API/session confundida con subagent | Se creó sesión HTTP pensando que equivale a invocar la herramienta nativa | Crea worker por la ruta documentada y exige que el worker lance hijos con `subagent` | Contar una llamada HTTP, fork o tab como uno de los hijos nativos | [API V2](https://opencode.ai/v2/docs/api/), [Tools V2](https://opencode.ai/v2/docs/tools/) |
| Herramienta o agente hijo no disponible | Error literal o catálogo sin el agente/modo necesario | Guarda el error literal, confirma catálogo/modo/permisos, corrige plan y scopes antes de un eventual reintento | Inventar agentes o lanzar `primary` como `subagent` sin modo permitido | [Agents V2](https://opencode.ai/v2/docs/agents), [Tools V2](https://opencode.ai/v2/docs/tools/) |
| Mínimo de dos hijos no alcanzado | Worker tiene cero o un hijo subagent verificado | Marca worker `partial`, `blocked` o `failed` según evidencia; no se puede marcar `verified` | Crear filas ficticias o declarar válido un solo hijo | [ledger-template.md](ledger-template.md) |
| Padre/sesión de hijo inválido | `parent_task_id`, runtime `parentID` o `sessionID` no apuntan al worker real | Detén y reconcilia identidad y la jerarquía antes de integrar; confirma las hijas con `GET /api/session?parentID=<sessionID del worker>` en lugar de fiarte del reporte (R14) | Usar relaciones DAG como propiedad padre-hijo | [ledger-template.md](ledger-template.md) |
| Scope de hijo fuera del worker | Scope infantil excede el presupuesto de escritura del worker | Bloquea ese hijo y vuelve a asignar scope autorizado | Permitir que el hijo herede un scope más amplio por estar en la misma sesión | [Agentes y seguridad](agents-and-safety.md) |
| Writer siblings solapados | Dos hijos hermanos escribirían en scope compartido al mismo tiempo | Aplica la [regla de scopes](agents-and-safety.md#presupuesto-de-escritura-y-scopes): dependencia y espera terminal del primero | Ejecutar ambos en paralelo o confiar en locks implícitos | [Agentes y seguridad](agents-and-safety.md) |
| Worker y subagent escribirían juntos en scope anidado | Worker modificaría una zona mientras hijo sigue activo/desconocido | Aplica la [regla de scopes](agents-and-safety.md#presupuesto-de-escritura-y-scopes): el worker espera al hijo, integra y solo después escribe | Confundir permiso de integración con escrituras simultáneas | [Agentes y seguridad](agents-and-safety.md) |
| Workers raíz con ámbitos compartidos | Dos workers independientes tienen rutas solapadas | Aplica la [regla de scopes](agents-and-safety.md#presupuesto-de-escritura-y-scopes): dependencias del DAG en orden | Suponer que distintas sesiones aíslan un mismo filesystem | [Patrones de asignación](agent-patterns.md) |
| Resultado desconocido o aprobación pendiente | Se perdió notificación, hay permiso `ask` pendiente o no hay outcome verificable | Conserva reserva de concurrencia y scope; reconcilia por capacidades publicadas ([reglas de espera](api-and-sessions.md#reglas-de-reconciliación-de-la-espera): permisos pendientes por `GET …/permission`, plazo re-armable); un `ask` pendiente es `awaiting-approval`, no un timeout; espera decisión explícita | Liberar scope/cupo, autoaprobar o relanzar prompt | [API V2](https://opencode.ai/v2/docs/api/), [Agentes y seguridad](agents-and-safety.md) |
| Informe del worker incompleto | Faltan inspección, integración, referencias de evidencia o resultado legible | Mantén `partial`/`blocked`, solicita complemento por canal confirmado y verifica artefactos | Marcar `verified` por resumen, silencio o tab visible | [Patrones de asignación](agent-patterns.md), [ledger-template.md](ledger-template.md) |
| Supuesto límite de concurrencia | Plan introduce un `max` fijo sin evidencia del runtime | Quita el límite; aplica la regla única del límite opcional | Importar un límite de versión anterior o tratar un tope hipotético como garantía | [ledger-template.md](ledger-template.md#límite-opcional-max_sessions_in_flight) |
| Reintento con efectos previos | Timeout o error ocurrió después de crear sesión, enviar mensaje o iniciar escritura | Verifica sesión, mensaje, aprobación y artefactos antes de repetir; conserva el mismo ID/acción cuando el contrato documente idempotencia | Duplicar trabajo por asumir que falló | [API y sesiones](api-and-sessions.md) |
| Borrado de sesión raíz | Se solicita eliminar worker con hijos | Exige aprobación para el ID exacto y advierte que la API documenta eliminación de hijos en cascada | Borrar a ciegas o asumir que conserva los hijos | [API V2](https://opencode.ai/v2/docs/api/) |

## Verificación de efectos antes de reintentar

1. Comprueba si la sesión exacta ya existe y si su `location`/`parentID` son los esperados. Si la respuesta de creación se perdió, el resultado sigue desconocido hasta reconciliarlo.
2. Comprueba por interfaces de lectura publicadas si el prompt/mensaje fue aceptado, ejecutado o está pendiente de aprobación. Si las lecturas no cubren todo el resultado, no reenvíes.
3. Inspecciona los artefactos y efectos de escritura en el scope autorizado antes de reanudar o reasignar el trabajo.
4. Tras una interrupción del worker, reconcilia cada subagent y sus aprobaciones. No liberes scopes solapados mientras alguna ejecución siga activa o desconocida.
5. Reintenta solo después de confirmar ausencia de trabajo previo y efectos, preservar autorización y scope, y usar argumentos publicados por la instancia.
