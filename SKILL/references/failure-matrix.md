# Failure matrix — OpenCode V2 two-level coordination

OpenCode's V2 HTTP API is declared experimental, including its session routes. The Action column is orchestrator policy, not a runtime promise. Before each operation, consult the confirmed instance's `/openapi.json` and follow the [verify-effects rule](#verify-effects-before-retrying). [API V2](https://opencode.ai/v2/docs/api/)

| Failure | Observable signal | Action | Do not | Anchor |
|---|---|---|---|---|
| Incomplete preflight | Instance, version, `/openapi.json`, permissions, or target agent unconfirmed | Block dispatch and record the missing evidence | Guess an endpoint, route, agent, or permission | [API V2](https://opencode.ai/v2/docs/api/), [Agents V2](https://opencode.ai/v2/docs/agents) |
| HTTP API absent/unauthorized | Endpoint does not answer, route missing from `/openapi.json`, or access denied | Do not create the session through undocumented mechanisms; leave the run blocked and request the authorized capability | Hunt for secrets outside the bounded exception in [recipe-tui-tabs.md](recipe-tui-tabs.md#direct-http-authentication-only-if-needed), scan ports, or switch transport to evade a denial | [API and sessions](api-and-sessions.md) |
| Worker creation without confirmed ID | Timeout/error from `POST /api/session` without an unambiguous `sessionID` | Reconcile existing sessions through the published routes before repeating; keep unknown state | Resend blindly and create duplicates | [API V2](https://opencode.ai/v2/docs/api/) |
| Mistyped root worker | Runtime `parentID` is not `null` or the ledger assigns it a parent | Stop the flow and fix/reconcile identity; only the orchestrator fixes the ledger | Treat a child session as a tab/root worker | [ledger-template.md](ledger-template.md) |
| Tab unavailable or not visible | `tabs.mode: off`, client without a selector, session does not appear after creation, or the gate says `blocked` | Keep creation and presentation separate. Run `orchestrate.sh tabs` to see the gate and its reason without effects: if it says `ready`, `init-run` exposes the tab; if it says `blocked`, the run continues without tabs and it is marked "not verified" — it is not a run failure. Only with the operator's explicit authorization do you use `--force-tabs`. Always verify by `sessionID` | Edit state without checking the gate; restart as automatic recovery; assume that creating the session via API opened a tab | [Local tabs recipe](recipe-tui-tabs.md), [TUI V2](https://opencode.ai/v2/docs/cli/tui/) |
| TUI version outside the expected branch | `version_ok=no`; the TUI is from another major, or older than the floor | The gate accepts any `2.x` `>=` the floor and blocks the rest. Raise the floor only with evidence that the schema did not change, not because the version exists. With the gate blocked, fail closed; `--force-tabs` is the operator's explicit authorization | Compare the version as if it were the guarantee; raise the pin to unblock without verifying the schema | [Local tabs recipe](recipe-tui-tabs.md#version-gate-branch-not-exact-pin) |
| Unknown private tabs schema or concurrent write | `tabs_status=fail-closed-esquema-distinto`, corrupt JSON, different shape, or the TUI modified `tabs.json` during the merge | The merge validates the shape **before** writing and fails closed with the file intact. Keep the backup, stop writing, confirm scope/schema, and guarantee the same `Flock` lock or effective TUI-writer exclusion during read/merge/rename/readback | Force the write, delete first, retry without exclusion, assume atomic writing prevents race loss | [Local tabs recipe](recipe-tui-tabs.md), [upstream storage v2.0.21](https://github.com/anomalyco/opencode/blob/v2.0.21/packages/tui/src/context/storage.tsx) |
| `init-run` reports `INCOMPLETO` (code 1) | Some worker was not created; the failed worker's line names it | Do not treat it as success. Re-run `init-run` with the same titles: name-based dedup reuses what already exists and completes what is missing | Declare the run finished, retry with `--force-new` (would create duplicates) | [Playbook P5](playbook.md#step-5-register-and-create-worker-sessions) |
| Duplicate session with the same name | Two sessions `Vermithrax` and `[01] Vermithrax` | Cause: the dedup slug included the ordinal, so the name search could not find the numbered session. The slug now ignores it; if it reappears, verify both sides use the same function | Compare titles as strings; use `--force-new` to "fix" it | [Naming convention](naming-convention.md) |
| Ambiguous tab identity | The visible tab cannot be associated with the created session's ID | Use a documented client interface that exposes the ID; otherwise do not verify | Use a tab's index, title, or color as the `sessionID` | [CLI plugin API](https://opencode.ai/v2/docs/build/plugins/cli/) |
| Different/unknown location | `Session.Info.location.directory` differs from `run.location.directory` or cannot be read | Do not dispatch; confirm the exact location on the same instance. Apply the server's canonical value literally on every client system | Rewrite separators, assume the client's local path is the server's path | [API V2](https://opencode.ai/v2/docs/api/) |
| API/session confused with subagent | An HTTP session was created believing it equals invoking the native tool | Create the worker through the documented route and require the worker to launch children with `subagent` | Count an HTTP call, fork, or tab as one of the native children | [API V2](https://opencode.ai/v2/docs/api/), [Tools V2](https://opencode.ai/v2/docs/tools/) |
| Child tool or agent unavailable | Literal error or catalog lacks the needed agent/mode | Save the literal error, confirm catalog/mode/permissions, fix plan and scopes before any retry | Invent agents or launch `primary` as `subagent` without an allowed mode | [Agents V2](https://opencode.ai/v2/docs/agents), [Tools V2](https://opencode.ai/v2/docs/tools/) |
| Two-child minimum not reached | Worker has zero or one verified subagent child | Mark the worker `partial`, `blocked`, or `failed` per evidence; it cannot be marked `verified` | Create fake rows or declare a single child valid | [ledger-template.md](ledger-template.md) |
| Invalid child parent/session | `parent_task_id`, runtime `parentID`, or `sessionID` do not point at the real worker | Stop and reconcile identity and hierarchy before integrating; confirm the children with `GET /api/session?parentID=WORKER_SESSION_ID` instead of trusting the report (R14) | Use DAG relations as a parent-child property | [ledger-template.md](ledger-template.md) |
| Child scope outside the worker | The child scope exceeds the worker's write budget | Block that child and reassign an authorized scope | Let the child inherit a broader scope for being in the same session | [Agents and safety](agents-and-safety.md) |
| Overlapping writer siblings | Two sibling children would write in a shared scope at the same time | Apply the [scopes rule](agents-and-safety.md#write-budget-and-scopes): dependency and terminal wait on the first | Run both in parallel or trust implicit locks | [Agents and safety](agents-and-safety.md) |
| Worker and subagent would write together in a nested scope | The worker would modify an area while a child is still active/unknown | Apply the [scopes rule](agents-and-safety.md#write-budget-and-scopes): the worker waits for the child, integrates, and only then writes | Confuse integration permission with simultaneous writes | [Agents and safety](agents-and-safety.md) |
| Root workers with shared scopes | Two independent workers have overlapping paths | Apply the [scopes rule](agents-and-safety.md#write-budget-and-scopes): DAG dependencies in order | Assume distinct sessions isolate the same filesystem | [Assignment patterns](agent-patterns.md) |
| Unknown result or pending approval | Notification lost, a pending `ask` permission, or no verifiable outcome | Keep the concurrency reservation and scope; reconcile through published capabilities ([wait rules](api-and-sessions.md#wait-reconciliation-rules): pending permissions via `GET .../permission`, re-armable deadline); a pending `ask` is `awaiting-approval`, not a timeout; wait for an explicit decision | Release scope/slot, auto-approve, or relaunch the prompt | [API V2](https://opencode.ai/v2/docs/api/), [Agents and safety](agents-and-safety.md) |
| Incomplete worker report | Missing inspection, integration, evidence references, or a readable result | Keep `partial`/`blocked`, request the remainder through the confirmed channel, and verify artifacts | Mark `verified` on a summary, silence, or a visible tab | [Assignment patterns](agent-patterns.md), [ledger-template.md](ledger-template.md) |
| Assumed concurrency limit | The plan introduces a fixed `max` without runtime evidence | Remove the limit; apply the single rule for the optional limit | Import a limit from an older version or treat a hypothetical cap as a guarantee | [ledger-template.md](ledger-template.md#optional-max_sessions_in_flight-limit) |
| Retry with prior effects | A timeout or error occurred after creating a session, sending a message, or starting a write | Verify session, message, approval, and artifacts before repeating; keep the same ID/action when the contract documents idempotency | Duplicate work by assuming it failed | [API and sessions](api-and-sessions.md) |
| Root session deletion | Deleting a worker with children is requested | Require approval for the exact ID and warn that the API documents cascading child deletion | Delete blindly or assume it keeps the children | [API V2](https://opencode.ai/v2/docs/api/) |

## Verify effects before retrying

1. Check whether the exact session already exists and whether its `location`/`parentID` are the expected ones. If the creation response was lost, the result stays unknown until reconciled.
2. Check through published read interfaces whether the prompt/message was accepted, executed, or is pending approval. If the reads do not cover the whole result, do not resend.
3. Inspect the artifacts and write effects in the authorized scope before resuming or reassigning the work.
4. After a worker interruption, reconcile every subagent and its approvals. Do not release overlapping scopes while any execution is still active or unknown.
5. Retry only after confirming the absence of prior work and effects, preserving authorization and scope, and using arguments published by the instance.
